# Обновление «для копирования 6»: улучшения импорта, дат изменений и поиска

## Что меняется

**1. Даты изменений по группам (главные страницы).**
Под строкой «Последнее изменение расписания» (и на гостевой главной, и на главной
админки) появилась ссылка «Изменения по группам ▾» — раскрывающийся список всех
групп с датой последнего изменения расписания конкретной группы. Группы
сгруппированы по форме обучения (очная/заочная/очно-заочная), есть поле фильтра
по названию (срабатывает на каждый введённый символ). Дата группы обновляется
автоматически при любом изменении её занятий (ручное редактирование, любой
импорт, удаление). Истории дат не было, поэтому при установке обновления всем
группам проставляется текущая глобальная дата — дальше даты расходятся по мере
реальных изменений.

**2. Две страницы очного импорта: ВО и СПО.**
Вместо одной страницы с переключателем ВО/СПО теперь две отдельные страницы:
«Импорт → Очная форма (ВО)» и «Импорт → Очная форма (СПО)» в сайдбаре
(и две кнопки на главной админки). Старый адрес `/admin/import/full_time_schedule/`
перенаправляет на страницу ВО. Заочный и очно-заочный импорт не менялись.

**3. Мультифайловый импорт очного расписания.**
На обеих страницах (ВО и СПО) можно выбрать сразу несколько .xlsx-файлов:

- после «Импортировать» слева появляется список записей (набор групп + имя файла);
  клик по записи показывает её расписание в сетке, ячейки можно править руками —
  правки не теряются при переключении записей;
- если новый файл содержит те же группы, что уже есть в списке, запись
  **перезаписывается**, дубликаты не накапливаются (главная претензия старой
  страницы);
- кнопка «Загрузить» сохраняет все записи разом: сохраняются только записи без
  ошибок и исчезают из списка; записи с ошибками остаются, подсвечиваются
  красным (в списке — вся запись, в сетке — конкретные пары с текстом ошибки);
  исправил ячейку — нажал «Загрузить» ещё раз;
- расписание групп полностью перезаписывается (как и раньше), перед сохранением
  автоматически создаётся резервная копия базы;
- записи можно убирать из списка крестиком; файлы, которые парсер не смог
  разобрать, сразу подсвечиваются красным с текстом ошибки.

**4. Живой поиск в справочниках и уведомлениях.**
На всех страницах со списками (преподаватели, группы, направления, аудитории,
дисциплины — просмотр/изменение/удаление — и списки уведомлений) поиск стал
посимвольным: результаты обновляются через ~0,35 с после ввода, без нажатия
Enter и без перезагрузки страницы (фокус в поле сохраняется). Появилась кнопка
«Сбросить». Поиск не различает регистр и буквы е/ё: запрос «Еремкин» находит
«Ерёмкина».

Попутно: адрес парсера в JS теперь берётся от текущего хоста (раньше был
захардкожен `tfcsu.ru:8001`); парсер понимает переменные окружения
`PARSER_HOST`/`PARSER_PORT` (по умолчанию — прежние значения, на сервере ничего
не меняется).

## Порядок установки на сервере

1. Останови сайт и парсер, сделай запасную копию проекта.
2. Скопируй файлы папки поверх проекта.
3. Выполни миграцию (обязательно — новое поле групп):
   `.venv\Scripts\python.exe -m django migrate main --settings=djangoProject.settings`
4. Выполни `collectstatic` (обязательно — изменился JS):
   `.venv\Scripts\python.exe -m django collectstatic --noinput --settings=djangoProject.settings`
5. Запусти сайт и парсер заново (перезапуск сайта обязателен: whitenoise кэширует
   статические файлы, а Django-процесс — скомпилированные шаблоны; без перезапуска
   будут отдаваться старые версии). `pip install` не нужен.
6. Проверка: на гостевой главной нажми «Изменения по группам ▾» — введи часть
   названия группы, список сузится на лету; в «Справочники → Преподаватели»
   начни печатать «Еремкин» — без Enter подтянутся «Ерёмкины»; «Импорт → Очная
   форма (СПО)» — выбери несколько файлов, нажми «Импортировать», проверь список
   слева, кликни по записи, нажми «Загрузить» — успешные записи исчезнут,
   ошибочные подсветятся красным.

## Если что-то пошло не так

Откат: вернуть прежние версии файлов из запасной копии, перезапустить сайт
и парсер. Миграцию 0028 откатывать не обязательно (поле `updated_at` с
`null=True` не мешает старому коду); для полного отката:
`python -m django migrate main 0027 --settings=djangoProject.settings`.
