# Для копирования 9 — стабилизация запуска: секреты, логи, кодировка консоли

## Что исправляется

Разбор октябрьских падений (упавший парсер, «само закрывшееся» окно сайта, кракозябры
в консоли) показал корневые проблемы. Этот пакет фиксирует их:

1. **Секретный ключ терялся при запуске планировщиком.** Переменные, заданные через
   `setx`, видны только пользователю, а задача автозапуска работает от SYSTEM — сайт
   стартовал с запасным ключом из кода. Симптомы: волна `Session data corrupted` в логах,
   разлогины, из-за этого же на сервере захардкодили `ALLOWED_HOSTS` в settings.py.
   Теперь секреты читает `server_env.bat` при каждом запуске (см. шаг 3 установки).
2. **Весь вывод — только в консоль.** При падении окно закрывалось вместе с ошибкой,
   причину восстановить было невозможно. Теперь сайт пишет в `logs\site.log` и
   `logs\django.log`, парсер — в `schedule-parser\logs\parser.log`; при падении окно
   остаётся открытым: в нём код ошибки и последние ~30 строк лога.
3. **Кракозябры и падающий pip.** Батник запуска на сервере был сохранён в UTF-8 с BOM
   (из-за этого первая строка `@echo off` превращалась в команду «я╗┐@echo»), pip парсера
   запускался при каждом старте и каждый раз падал на Python 3.15 (нет готовых wheel-ов
   pydantic-core, компилятора на сервере нет). Теперь: `chcp 65001` + `PYTHONUTF8=1`
   во всех батниках, pip при запуске НЕ выполняется (зависимости парсера ставятся
   отдельным `install.bat` один раз), `fastapi[all]` заменён компактным набором.
4. **Фикс импорта заочной/очно-заочной формы**: кнопка «Загрузить» без выбранного файла
   больше не отправляет в парсер пустоту (это был источник ошибки 422 в логах парсера);
   адрес парсера берётся от текущего хоста вместо захардкоженного `tfcsu.ru:8001`.

## Изменённые файлы (копировать с сохранением структуры)

```
├── запуск_сервера.bat                     (переписан: server_env, лог, окно с ошибкой)
├── server_env.bat.example                 (НОВЫЙ — шаблон секретов)
├── backup_daily.bat                       (читаемый UTF-8 лог бэкапов)
├── djangoProject/settings.py              (+ секция LOGGING; хардкод ALLOWED_HOSTS убран)
├── main/static/js/importPartTimeSchedule.js
├── main/static/js/importMixedSchedule.js
└── schedule-parser/
    ├── start.bat                          (переписан: лог, БЕЗ pip при каждом запуске)
    ├── start_local.bat                    (локальный запуск — на сервер не влияет)
    ├── install.bat                        (НОВЫЙ — разовая установка зависимостей)
    ├── main.py                            (dev-режим reload — только локально)
    └── requirements.txt                   (fastapi без [all] + python-multipart)
```

На сервере также **удалить** устаревший `запуск_на_сервер.bat` (он поднимал отладочный
`runserver` на прод-порту 8100).

## Установка на сервер

1. Остановить сайт: `schtasks /End /TN "TFCSU_Schedule_Site"` (или закрыть окно).
   Если открыто окно парсера — закрыть и его.
2. Скопировать файлы из этой папки поверх проекта **с сохранением структуры каталогов**.
   `db.sqlite3` не трогаем.
3. **Главный шаг — создать `server_env.bat`** (один раз):

   ```
   copy server_env.bat.example server_env.bat
   ```

   Открыть его блокнотом и заполнить `DJANGO_SECRET_KEY` — тем же ключом, который уже
   используется на сервере (он записан в `ЧИТАЙ_МЕНЯ_ПЕРЕД_УСТАНОВКОЙ.txt` рядом с
   проектом). Если задать новый ключ — у всех слетит вход. Проверить соседние строки:
   `DJANGO_DEBUG=False`, `DJANGO_ALLOWED_HOSTS=tfcsu.ru,localhost,127.0.0.1`.
   Этот файл не коммитится в git и никуда больше не копируется.
4. Один раз вычистить сессии, оставшиеся от старых ключей (иначе в логах ещё до двух
   недель будет сыпаться «Session data corrupted»; всем придется просто войти заново):

   ```
   .venv\Scripts\python.exe manage.py shell -c "from django.contrib.sessions.models import Session; Session.objects.all().delete()"
   ```

5. Обновить зависимости парсера (новый компактный requirements; уже установленным
   версиям это не повредит — pip лишь сверит список): запустить `schedule-parser\install.bat`.
   Если pip начнёт ругаться на сборку pydantic-core — пропустить этот шаг: текущие
   библиотеки продолжат работать.
6. **Обязательно**: пересобрать статику (исправлены два JS-файла) и запустить сайт:

   ```
   .venv\Scripts\python.exe -m django collectstatic --settings=djangoProject.settings --noinput
   schtasks /Run /TN "TFCSU_Schedule_Site"
   ```

   (или запустить `запуск_сервера.bat` вручную и посмотреть на окна сайта и парсера).

`migrate` НЕ требуется. Задачи планировщика не меняются (путь запуска тот же).
Старые `setx`-переменные больше не используются — можно не удалять.

## Проверка после установки

- В окне запуска: кириллица читается, первая строка не ругается на «я╗┐@echo»,
  есть сообщение «Сайт запускается...».
- Появились и наполняются: `logs\site.log`, `logs\django.log`,
  `schedule-parser\logs\parser.log` — открыть и убедиться, что в них UTF-текст.
- `http://127.0.0.1:8100` открывается, вход под админом работает (после чистки сессий —
  с повторным вводом логина/пароля).
- Страница импорта заочной формы: нажать «Загрузить» без выбора файла — красная плашка
  «Не выбран файл» вместо ошибки парсера.
- Загрузить реальный файл расписания — в `schedule-parser\logs\parser.log` появляется
  `200 OK` на `/schedule/parser/schedule/parse`.
